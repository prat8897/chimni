A 2D dataflow language

Layout is grammar.

Most languages tell the machine how. Chimni says what flows where. A cell consumes the cell on its left. A new row is an independent chain. Inputs and outputs live in the syntax. There are no loops and no temporary variables.

$[orders,min_total]{(customer,total)}
@orders  #(customer)  +s(amount)  ?>[min_total]  ~\(total)  ^

take orders → group by customer → sum amount → keep totals above min_total → sort descending → emit

Read it in two minutes

  
In Sanskrit, a word's ending tells you its role in the sentence. Chimni borrows that idea: position is grammar.


  

    

      
→

      
Right means “consume the cell on my left”

      
Each cell takes the previous cell's output. A row is a pipeline, read left to right.

      
@users  ?(age)>=[18]  *(name)  ~/  ^

    

    

      
↓

      
A new row is an independent chain

      
Rows can't see each other unless they say so, so a runtime may run them in parallel. Each ^ fills the next output.

      
@orders  #(customer)  +s(amount)  ^
@orders  .            +s(amount)  ^

    

    

      
'

      
A quote reads the cell above

      
' is one row up, '' two rows up, same column. Joins happen by position, not by name.

      
@sales  #(cat)  +s(amount)
@sales  .       +s(amount)
.       .       ''/'        ^

Signatures are contracts

      
Inputs in [ ], output shapes in { }. Emit the wrong shape, or none where it isn't allowed, and it's an error.

      
$[transactions,limit]{id|none}

The fair comparison

  
Comparing Chimni with loop-and-dict Python flatters it. So every example also has an idiomatic
    pandas, SQL or jq version, written the way someone fluent would write it.
    All three versions are run against each other on hundreds of random inputs in CI, so they really do compute the same thing.

Where the others win

      
jq and SQL are as short as Chimni, sometimes shorter. SELECT name FROM users ORDER BY age DESC LIMIT 1 is
        hard to beat. Most of Chimni's lead over Python disappears once you compare it with a tool built for the job.

    

    

      
Where Chimni is different

      
The output shape is part of the grammar, so “I said pairs but built a triple” fails with a row and column.
        Independent rows are visibly independent. Ties are deterministic: the SQL versions need an explicit
        ORDER BY …, MIN(rowid) to agree with the others when totals are equal.

    

    

      
What's still unproven

      
The bet is that a small, regular notation is easy for an LLM to write correctly and cheap to read.
        Token counts above are cl100k_base; whether models actually write Chimni better is untested.
        Help measure it.
